# Skiff effects review and integration handoff

Reviewed 2026-10-19 against Skiff commit `eda8de411e5b1314e6f5d4a7170ab9cd886f5845` (main at review time). Source was inspected in ignored `build/skiff-review-source`; no Skiff production code imported. Local comparison uses the existing uncommitted MerthSloop checkout, not HEAD. No repository AGENTS.md was found at workspace/parent roots or within the workspace.

## Recommendation

Keep MerthSloop's current stereo FDN reverb by default. Prototype SPRING first for a distinct new sound; evaluate Skiff HALL only as an optional replacement after blind listening and target profiling. Prefer small isolated ports over replacing fx.c or perform.c. Existing INSERT effects already cover most of Skiff's effect inventory.

## Implemented: wet live octave down

`PX_OCT` retains ID 20 and physical key index 10 (D#4, MIDI 63), formerly OCT UP. Names now say OCT DOWN / oct down. Two triangularly crossfaded interpolated ring taps grow their delay by 0.5 sample per output sample, so the read speed is 0.5x. Delay window remains 2,048 samples; wrap takes 4,096 output samples. No new buffer/state or change to HALF/other effects; existing 64-sample entry/release fade remains. This is an independent adaptation of the existing SLOOP shifter, not imported Skiff harmonizer code. Two fractional reads replace two integer reads, increasing active OCT arithmetic; idle cost/storage is unchanged. Parent reports target budgets and inlining checks pass in the packaged build. Physical audio deadline margin remains unmeasured.

Limit: this basic rotating-delay shifter has window sidebands and pitch-dependent cancellation; it is not transparent pitch shifting. An exploratory 110 Hz input strongly attenuated the desired 55 Hz component (RMS about 0.59 of dry, with sidebands). The existing two-tap method can cancel when tap spacing puts the source near opposite phase. Passing 220/440/1760 Hz checks does not establish uniform bass response. A longer/adaptive window or pitch-synchronous/spectral shifter needs a separate listening/CPU tradeoff; do not claim a clean sub-octaver for every source.

## Design only: HALF should slow the running song

Current HALF is a captured beat/2 ring span replayed at half speed, with ring protection after capture. Thus it repeats the captured material rather than advancing the sequencer slowly; the user's observation is correct. Keep ID/key 7, replace its behavior in a separate routing change after agreeing the following semantics.

Recommended first implementation: momentary 0.5x **musical transport**, preserving note pitch. Press takes effect at next audio-control block, release restores 1x at the current song position, without resetting phase, rewinding, jumping to a wall-clock catch-up position or retriggering sustained voices. Song/scene/step/arp/ratchet/gate/metronome advance on the slowed musical clock. Free-running oscillator pitch, millisecond envelopes, reverb decay and existing audio tails remain real-time. Beat-synced LFO/envelopes/slicer/duck/punch grids and delay time should follow the effective musical rate. Active delay taps must glide/crossfade to avoid clicks. Tempo display and saved BPM remain unchanged; show a transient HALF indicator. If the intent includes an octave pitch drop like tape playback, that is an additional requirement: transport slowing alone preserves pitch, and resampling only the final mix still has an ever-growing backlog. Do not imply that a finite delay ring can continuously half-speed unrestricted live audio.

Implement one volatile/realtime gesture state and rate helper, not writes to song.g[G_BPM] (40-BPM floor would break 40→20, project saves could capture the gesture, and release could overwrite a tempo edit). Use integer time units with retained fractional remainder, e.g. scale adv with `(adv + remainder) / 2`. Audit all direct BPM reads: events_block's adv, clkout_block, count-in, groove_preview, voice sync/esync_coef, delay_samples, beat_samples/clk_samples, duck_block, slicer, tempo LFO and scene/arranger paths. clk_samples currently divides by nominal BPM; changing only adv would give inconsistent punch alignment. Ensure core 1 sees one block-consistent rate snapshot. Releasing HALF while stopped should clear only the gesture, never issue transport start.

MIDI policy must be explicit before implementation: recommend internal-clock-only HALF for the first release; when slaved to incoming MIDI clock, disable the gesture visibly. Silently halving local sequencer time while leaving upstream clock/phase interpolation and outgoing clocks unchanged will desynchronize devices. For internal master operation, outgoing MIDI clock should follow effective musical rate (24 pulses per slowed quarter), with no extra START/STOP on press/release. A later slave mode would need separate external and local phase domains, defined resync behavior and doubled local clock division; do not patch mclk_adv with a blind /2. Incoming note-through remains real-time.

Tests required: exact phase over odd block advances; 40/120/240 BPM; repeated press/release without drift or attacks; song boundaries/scenes/arp/ratchets/ties/gates/count-in; BPM edits and save while held; tempo-sync versus free envelopes/LFO; delay changes over a ringing tail; internal output clock pulse counts and no transport messages; disabled slave-clock behavior; STOP/disconnect/layer exit/panic; direct/mapped MIDI and physical ownership. Parent should approve these semantics before implementation.

## Design only: combinations of effects

Current routing is single-owner: key_down replaces punch.req/keybit; key_up clears only the latest owner, so releasing the latest effect does not resume an earlier held key. Shared `punch` state makes running punch_process once per held effect incorrect: it would advance/write the same ring repeatedly and alias filter/ramp state.

Use Skiff's principle, not its full implementation: one selected ring effect plus independently owned streaming stages. Maintain physical-held and MIDI-held masks separately, an ordered ring-owner stack (last pressed wins; releasing it resumes most recent still held), and remote lease state under existing physical priority. Keep remote protocol's sixteen-effect contract unchanged; old remote requests remain one effect until a versioned extension is designed. Snapshot requests atomically per audio block. Clear masks on layer exit/STOP/panic and MIDI disconnect; unrelated source releases must not release another source's same effect. Do not add latch by implication.

Practical bounded first set: one ring stage (loops/reverse/stop/rewind/octave/flange/wobble/echo) -> one spectral stage (LPF/HPF/PHONE or a kill) -> CRUSH or ALIAS -> GATE -> PAN or MONO -> FADE. HALF becomes the separate transport gesture and can combine with all stages. FREEZE remains exclusive with ring effects initially because it controls reverb send/hold upstream; support FREEZE + cheap downstream stages only after freeze lifecycle tests. Conflicting filters, crush/alias and pan/mono each use last-pressed priority with fallback; at most one from each family. This keeps all key positions and avoids running all three kill filters together. Define whether ECHO feeds the shared original dry ring or the processed signal; recommend original dry capture once per sample for first release, so stacking does not silently create feedback loops. Ring ownership for captured loops continues to protect held material. Resume a displaced ring effect with a fresh capture/start and crossfade, not stale shared indices.

Refactor dry-ring capture and ownership once per sample; extract selected wet ring sample and streaming stages with independent small states/ramps. Kills require 64 bytes of stereo SVF state plus coefficient/work blocks; retain current kl/kr scratch reuse, not one buffer per held key. Per-stage gains must ramp independently so releasing one does not bypass others; the current whole-effect fade cannot express that. Clamp intermediate bounds consistent with existing headroom and keep final limiter. Publish active stages/key LEDs from one state snapshot. Existing FX+octave-button throws remain independent and retain their held behavior.

CPU admission: profile worst case (ring interpolation + stereo KILL MID + crush/alias + gate + pan) with maximum engines and two-core traffic before enabling every combination. If deadline headroom is insufficient, cap DSP stages by documented family admission rather than dropping samples or silently bypassing held keys. RAM should remain mostly state/scratch (hundreds of bytes), no second 64-KB ring; flash is the primary immediate integration constraint. Exact numbers require the refactor and target build.

Tests required: every valid pair and representative maximal chain; incompatible last-press/fallback/release permutations; same effect held by physical/MIDI; remote lease cleanup; arbitrary release order; crossfade continuity and exact dry after final release; held loop preservation across ring wrap; FREEZE capture/decay and other tails; HALF combinations; keyboard never plays/records effect keys; deterministic fuzz and hot full-scale boundedness; per-stage target deadline/memory/flash checks. First ship a small verified subset if needed.
